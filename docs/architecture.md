# Architecture

The authoritative design is in [DHARMANET_MASTER_PLAN.md](DHARMANET_MASTER_PLAN.md) (§3–6). This page describes what
is implemented.

## Request flow

```
POST /api/analyses
  └─ AnalysisPipeline.run                         backend/app/services/pipeline.py
       1. structure      heuristic.structure_dilemma  | LLMBackend.structure (4 prompts, per-stage fallback)
       2. evaluate       for fw in REGISTRY: fw.evaluate(d) | LLMBackend.evaluate_framework (isolated prompt per framework)
       3. dharma         DharmaEngine.retrieve → evaluate | LLMBackend.dharma → validate_citations
       4. annotate       explanation.annotate_disagreements (deterministic)
       5. matrix         decision.engine.build_matrix (normalise, aggregate, rank, recommend; user + equal weights)
       6. sensitivity    decision.sensitivity.analyze (exact flip thresholds, seeded Monte-Carlo)
       7. explanation    explanation.explain + compare
  └─ Repository.save → analysis_runs (+ normalised child tables)
```

`/rescore` re-runs only steps 5–7 (no semantic stage). `/revise` applies human edits and re-runs 2–7 as a new
run linked by `parent_id`.

## Module map

| Module | Responsibility | Deterministic? |
|---|---|---|
| `services/dilemma/heuristic.py`, `lexicon.py`, `action_templates.py` | offline structuring | yes |
| `services/llm_backend.py` | LLM stage implementations + response schemas | no (validated) |
| `services/ethics/frameworks.py` | 6 framework evaluators, registry | yes (heuristic path) |
| `rag/knowledge.py`, `rag/retriever.py` | KB loading/validation, TF-IDF + tag retriever | yes |
| `services/dharma/engine.py` | concept rules, citation validator | yes |
| `services/decision/*` | aggregation, ranking, sensitivity | yes |
| `services/explanation/engine.py` | explanation, trace, comparison | yes |
| `llm/base.py`, `llm/structured.py`, `llm/prompts.py` | providers, JSON validation loop, versioned prompts | — |
| `models/orm.py`, `models/repository.py` | persistence | — |
| `api/` | routes, auth, rate limit | — |

## Extending

* **New framework:** subclass `Framework` in `services/ethics/frameworks.py`, add a dimension to `schemas/evaluation.DIMENSIONS`,
  a default weight in `schemas/decision.DEFAULT_WEIGHTS`, register it in `REGISTRY`, and bump `FRAMEWORK_VERSION`.
* **New LLM provider:** implement `complete(system, user) -> str` and add it to `make_provider`.
* **Vector retriever:** implement the `Retriever` protocol (`retrieve(query, tags, k)`) and pass it to `DharmaEngine`.

## Deliberate deviations from the original brief

* **No Qdrant by default.** The KB has 28 records and retrieval must be reproducible; an in-process lexical retriever is
  used behind a `Retriever` protocol.
* **No Redis / background workers.** A heuristic analysis takes ~0.1 s; LLM runs are synchronous. The rate limiter is
  in-memory (per process).
* **Explanations are deterministic,** assembled from recorded outputs rather than generated by an LLM, so they cannot
  drift from the numbers they explain.
